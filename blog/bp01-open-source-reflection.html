Open Source as a Contributor and as a User

Prior to this summer, I did not question who created these applications while using open source software daily. The software such as Git keeps track of my progress, VS Code is where I code, and Python and HTML are the languages I use to create my projects. All of them are free, and I did not wonder about anything until joining SSDT for the first time and contributing to CAS and BCSR software, which I have been using for a long time as a student at Berea and which are widely used by the faculty and staff members.

The greatest thing is that open source has taught me almost as much about people as code. Participating in open source involved reading code I had not written myself. The CAS and BCSR algorithms were difficult to comprehend initially as many of their features occur behind the scenes, and this required me to figure out how they fit together in order to make changes. This realization helped me understand the system better than any assignment ever would. It also showed me that behind every line of code is a person who made a choice, and understanding their reasoning mattered as much as understanding the code.

Additionally, it taught me to effectively communicate. An issue or pull request would be meaningless unless someone else comprehended it, and so I had to learn to clearly describe the changes that I made and the reasons for those changes. It has also taught me the importance of documenting everything properly. There have been numerous instances where I have opened a project where the README was outdated or even absent, wasting countless hours trying to figure out how to set up the project.

Open source software does have its shortcomings, and I can vouch for that. I have often found myself waiting for days before someone reviews or merges my changes, which only serves to slow me down. The codebase might be of high quality in one area, but of low quality in another, lacking even basic comments. This has almost never been anyone's doing. There are only so many hours in a day.

Although there are some issues with open source, I still consider that open source is a good way to build software infrastructure and technical skills. In terms of technicalities, the advantage of open source is the transparency of any problems. In ethical terms, open source brings value to all participants, whether it is a student like me contributing or our college that uses CAS and BCSR.

I have 8 story points in CAS and BCSR. This number was achieved through completion of one big feature, the Course List Upload. The feature allows a user to upload an Excel file, verify the extracted information, and submit it. There is not one thing to be done, but several things linked to each other. Correct interpretation of the Excel file, validation of data before it reached the review screen, and submission of the reviewed information took me longer than expected. Also, it took time to get familiar with the internal workings of CAS and BCSR before doing anything with it. Also, the review process influenced story points; a task cannot be considered complete until it is merged. In the future, it will help me to break down features into small stories.
